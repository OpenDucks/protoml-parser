Workflow 6: Release Operations Without A Board Story

Not every workflow revolves around Board approval. Sometimes Release Operations just needs a practical, low-drama process for checking a ProtoML delivery set, its supporting records, and the files that will actually be handed to other people.

The scenario

Lea is now working on the operational release checklist itself. This file may not need a board signature at all. It still needs to be structurally valid, internally reviewable, and consistent with the ProtoML files, imports, macros, and rendered outputs that will be distributed.

Validate the release record

protoparser validate "./governance/release-checklist.pml" -trust=warn

Here the goal is not necessarily strict signature enforcement. The goal is to catch structural problems before publishing.

Inspect the release-related document set

protoparser register "./governance" statistics

This gives Lea confidence that the current release record sits inside a healthy governance set.

Prepare the delivery form

Lea now decides what the receiver should actually get:

  • the editable .pml source tree when the receiver should keep authoring
  • a bundled snapshot when the receiver should get one self-contained handoff
  • HTML or PDF when the receiver only needs a reader-facing result
protoparser bundle "./governance/release-checklist.pml"
protoparser "./governance/release-checklist.pml" html
protoparser "./governance/release-checklist.pml" pdf

Check what must travel with the file

  • imported .pml files when the delivery is not bundled
  • local macros when the document depends on them
  • matching *.sig.json sidecars when signed files are distributed
  • referenced local assets such as images or attachments

Bundled macros from {{macro_dir}} do not need to be shipped separately when the receiving side already uses the standard ProtoML installation.

Why this workflow is different

  • it is about release readiness, not primarily signer identity
  • trust checks may still matter, but they are only one part of the delivery checklist
  • missing imports, missing assets, or missing sidecars are often the real failure mode

When the registry story comes back

If the release record uses external macros, or if trust lookups come from more than one place, Lea may need to combine an internal author registry with a separate macro registry.
